Every file below is the file that deploys, imported at build time rather than pasted.
A copy that can drift is a copy that will, so a check in CI fails the moment what is
published here differs from what is in `terraform/`.

<Aside type="note" title="Why the configuration is imported rather than shown inline">
Pasted into a code fence, this configuration would be part of the page source, and the
page source is translated into twelve languages. The comments inside it would be
translated with it, and each locale would publish a different, wrong configuration.
Imported, it never enters the page source at all.
</Aside>

## Root module

### `terraform/backend.tf`

Dedicated AWS S3 backend; its configuration is supplied at init time and not
committed. The separate `terraform/bootstrap/state-backend` stack creates its
KMS-encrypted, versioned bucket and native lockfile support before the showcase
is initialized. It also configures server-access logging, EventBridge object
notifications, and an independently encrypted cross-region recovery replica.

<Code code={backend} lang="hcl" title="terraform/backend.tf" />

### `terraform/bootstrap/state-backend`

The bootstrap is fully declarative. It derives globally unique replica and log
bucket names from the primary bucket, creates the regional KMS policies and S3
controls, and exposes non-secret backend settings for both the showcase and the
bootstrap state.

<Code code={backendBootstrapVersions} lang="hcl" title="terraform/bootstrap/state-backend/versions.tf" />

### `terraform/data.tf`

Read-only lookups, including the Azure AD identity used to derive the deployer.

<Code code={data} lang="hcl" title="terraform/data.tf" />

### `terraform/kvm.tf`

Declarative KVM & libvirt infrastructure managed natively via `dmacvicar/libvirt`.
The network name and bridge are generated from the stable CE MAC/IP map; each CE
therefore receives the same reserved address after a replacement. The base volume
uses the F5-issued KVM appliance URL from `xcsh_site_image`, never a generic cloud
OS image.

<Aside type="caution" title="Sales Demo image prerequisite">
The KVM image lookup is deliberately fail-closed. The Sales Demo tenant must expose
exactly one valid tenant-owned `maurice_config`; this is a platform prerequisite,
not Terraform-managed infrastructure. With `xcsh` v9.5.0, planning resolves
`External tenant prerequisite unavailable` before any apply, libvirt, Docker,
Azure, or F5 configuration mutation. Keep `enable_kvm = false`
(the default) to omit KVM from an unrelated apply or to produce a KVM-only destroy
plan without querying that image endpoint.
</Aside>

<Code code={kvm} lang="hcl" title="terraform/kvm.tf" />

### `terraform/kvm_frr.tf`

The router is a Terraform-owned, digest-pinned FRR container attached to the
generated libvirt bridge through Docker macvlan. Its exclusive BGP address is
`10.100.0.2`; `10.100.0.1` remains the libvirt NAT gateway.

<Code code={kvmFrr} lang="hcl" title="terraform/kvm_frr.tf" />

### `terraform/locals.tf`

Where the derived object names live. Terraform variable defaults cannot reference other variables, so each name variable defaults to null and is resolved here.

<Code code={locals} lang="hcl" title="terraform/locals.tf" />

### `terraform/aws_ce.tf`

AWS Customer Edge EC2 nodes, IAM role/profile, key pair, ordered dual network interfaces, Elastic
IPs, and an explicit 100-GiB Marketplace AMI root volume. Terraform creates the site before its
site-bound JWT token, obtains provider-issued cloud-init, injects multipart user data, and discovers
and approves runtime registration. The certified AMI retains ownership of `/etc/vpm/config.yaml`;
the provider payload writes `/etc/vpm/user_data`.
See [the SMSv2 lifecycle](../../customer-edge/smsv2/terraform-lifecycle/).

<Code code={awsCe} lang="hcl" title="terraform/aws_ce.tf" />

### `terraform/cloud-init/ce-node-aws.multipart.tpl`

AWS multipart wrapper: early SLI route guard, provider-issued bootstrap payload, and operator SSH access. It preserves certified image configuration. The placeholders below are Terraform template inputs, not rendered credentials.

<Code code={awsCloudInit} lang="text" title="terraform/cloud-init/ce-node-aws.multipart.tpl" />

### `terraform/aws_upgrade.tf`

<Code code={awsUpgrade} lang="hcl" title="terraform/aws_upgrade.tf" />

AWS Transit Gateway Connect uses provider v8 MAC-bound SMSv2 configuration and runtime observations with AWS-authoritative transport facts.
